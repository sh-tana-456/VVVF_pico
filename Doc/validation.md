# ビルドと検証

## ビルド

Pico SDK、ARMツールチェーン、CMake/Ninjaが必要。既存環境ではSDK 2.3.1、arm-none-eabi-gcc 14.2、Releaseで確認した。

```sh
cmake -S . -B build -DPICO_BOARD=pico
cmake --build build -j4
```

SDKを検出できない場合は `-DPICO_SDK_PATH=/path/to/pico-sdk` を指定する。生成された `build/vvvf-pico.uf2` をPicoのBOOTSELドライブにコピーする。本作業では`picotool load -v -x build/vvvf-pico.uf2 -f`で接続中のPicoに書き込み、検証と再起動を行った。

## ホストテスト

```sh
./tests/run.sh
```

ホストのC11コンパイラ、libm、ASan/UBSanが必要。SDKをリンクせず実際のcontrol/modulator実装をテストする。生成バイナリは/tmpに置き、終了時に削除する。実行環境のptrace制約のためLeakSanitizerだけ無効化している（テスト対象に動的メモリ確保はない）。

確認内容:

- IGBT/GTOの境界、非数・負値、110 Hz上限、加減速と両押し。
- N=3,5,7,9,11,13,15の同期波形が基本波1周期後に同じになること。整数位相で周期数を検証。
- 独立した浮動小数点の正弦波・三角波モデルとの非同期出力比較。
- 低変調率でも各相の平均デューティが約50%であること。
- 出力の基本波成分の三相位相差が120°/240°であること。
- 非同期↔同期、同期比変更、下降方向の境界通過、停止時Low。
- 時間指定ワードの容量上限、各フレームの継続時間合計、微小変調率での差動パルス面積。
- 固定したN=3の位相関係と、逆ゲイン表適用後の基本波振幅。
- 追加音プリセットのキャリア補間、0～110 Hzの走査、パターン名による選択。
- 公開データ3321点の独立照合、広域3パルスの角度オラクルと参照比較式、1パルス矩形波。
- [変調率変更の追従](amplitude-tracking.md)：静的/動的振幅、基本波位相の継続、1近傍のパルス消失。

ホストテストはPIO命令実行、DMAチェーン、転送期限、USBとの競合を検証しない。

## 実機測定の結果

2026-11-12にRP2040 Pico、Saleae互換fx2lafwロジアナで測定済み。CH0=U、CH1=V、CH2=W、電力段は未接続。詳細と再生可能なファイルは[実測記録](measurements-2026-11-12.md)を参照。GTOプロファイル、故障注入、長時間耐久は未実施。追加の公開プリセット28動作点は[移植仕様と測定結果](preset-sources.md)を参照。

## 実機での追加確認手順

最初はゲートドライバ・電力段を接続せず、GP20/21/22とGNDをロジックアナライザへ接続する。低速の微小パルスを観測するため、12 MHz以上で取得する。今回のロジアナの12 MHzは83.3 ns刻みなので、PIOの24 ns最短区間は測定器では直接検証できない。

1. 起動後0 Hzで三相Low、USBログの`fault=0`を確認する。
2. GP16をGNDに接続し、約5 Hz/sで加速することを確認する。GP17で減速、同時押しで維持、110 Hzで飽和することも確認する。
3. 非同期域10/20/39 Hzで、キャリア約1 kHz、線間信号U-V/V-Wの基本波が設定周波数、位相順が仕様通りであることを確認する。基本波の測定はGPIOエッジの数ではなく線間波形のFFTや低域通過後の信号で行う。
4. 45 Hz（N=9、fc=405 Hz）、55 Hz（N=3、fc=165 Hz）で長時間取得し、基本波に対するスイッチングパターンの滑りがないことを確認する。制御点の正弦波LUTと交点の線形補間に伴う小さい誤差はあり得る。GPIO出力の立ち上がり数が常にNになるという判定はしない。
5. 39.9↔40.1、49.9↔50.1 Hzを往復し、基本波位相がゼロへ飛ばないこと、長い停止や不自然な繰り返しがないことを確認する。同期モードではキャリア位相を規定位相へ合わせるため、切り替え中の各パルス幅は変化する。
6. GTOプロファイルで同様に46/60/70 Hz境界と80 Hz以上を確認する。
7. USB接続・未接続、ログ読取りあり・なしで数分動かす。`fault=0`を維持すること、`render_max`が2560 µsを十分下回ることを確認する。目安として最大1280 µs未満の余裕を求め、実測に応じてFs・ブロック長・演算を調整する。
8. 停止まで減速し、キュー分の遅延後に全出力Lowになることを確認する。
9. 検証専用ビルドでバッファ生成を意図的に3 ms以上遅延させ、`fault=1`・三相Low・再起動まで復帰しないことを確認する。遅延コードは通常ビルドへ残さない。

測定結果（基板、clk_sys、Fs、各モード周波数、render_max、fault、キャプチャ）を保存してから電力段の検討へ進む。確認済み項目と未実施項目は実測記録に分けて記載した。
