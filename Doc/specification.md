# VVVF Pico 仕様

## 目的と実装状況

対象はRP2040のRaspberry Pi Pico。三相の正弦波指令と三角波キャリアを比較し、GPIOに三相SPWMを出力する。PIO＋DMA方式へ変更し、PWMペリフェラルのphase-correctモードは使用しない。

Pico SDK 2.3.1でビルドし、接続済みRP2040 Picoへ書き込み済み。ホストの数値テストに加えて、2026-11-12にロジアナでIGBT各動作点を測定した。結果は[実測記録](measurements-2026-11-12.md)を参照。電力回路での検証はしていない。

実装の図、IRQ回数、計算レート、`sync3_reference`の詳細は[実装構成](architecture.md)、追加音プリセットは[音再現パターン](audio-patterns.md)を参照。

## 元コードで問題になっていた点

- phase-correct PWMのwrap IRQは谷で発生する。TOPでのIRQはなく、CC/TOPの更新も谷でラッチされるため、山と谷で指令を更新する前提は成立しない。
- `carrier = f1 × N × 2` と `1/(2N)` の位相ステップ、3パルスだけの6ステップ処理が混在していた。モードの意味を統一する必要があった。
- 元の`MR × (0.5 + 0.5 sin)`と現在の`0.5 + 0.5 MR sin`は共通モードの置き方が違う。理想的な相補駆動・浮動中性点の三相負荷では、同じMRなら線間のPWM周期平均電圧は同じであり、元式自体の誤りではない。現在は微小パルスをドライバへ通しやすい50%中心を採用する。
- mainからIRQに渡すパラメータが個別更新され、位相ステップ・キャリア・モードに不整合が起こり得た。
- 割り込み中のPWMカウンタの逐次ゼロクリアは各スライスの位相をずらし、周期を切り詰める。
- 周波数の上限がなく、テーブル範囲外で以前のモードが残っていた。

参考: [SDK hardware_pwm](https://www.raspberrypi.com/documentation/pico-sdk/hardware.html#hardware_pwm)、[公式pwm.h](https://github.com/raspberrypi/pico-sdk/blob/master/src/rp2_common/hardware_pwm/include/hardware/pwm.h)。これらのPWM制約を受けない出力経路を採用した。

## 入出力と操作

| ピン | 用途 |
|---|---|
| GP22 | U相 |
| GP21 | V相 |
| GP20 | W相 |
| GP16 | UP、内部pull-up、GND接続で加速 |
| GP17 | DOWN、内部pull-up、GND接続で減速 |

3出力は外部ゲートドライバのハイサイド用指令。ドライバ側でローサイドの相補信号を生成する構成を想定する。入力LowがローサイドONになる構成では、全信号Lowは全素子OFFではなく下側ゼロベクトルになる。

3出力は連続GPIOである必要がある。出力ワードはbit0=W、bit1=V、bit2=U。PIOのOUT命令で3ピンを同時更新する。三相の順序は元コードの逆転設定を引き継ぎ、U=θ、V=θ+240°、W=θ+120°。反転する場合はmodulatorのV/Wオフセットを入れ替える。

起動時は0 Hz、全出力Low。UP/DOWNは100 Hz程度で読み、5 Hz/sで加減速する。同時押しは維持、範囲は0～110 Hz。ループ遅延は実時間から計算し、1回の積算時間は50 msまでに制限する。ボタンの専用デバウンスは未実装。

## USB測定コマンド

USB CDCへ改行付きで以下を送れる。これは実機測定を再現するための設定インターフェース。

| コマンド | 動作 |
|---|---|
| `f 1` | 1 Hzを即時設定して保持 |
| `r 5` | 現在値から5 Hzへ5 Hz/sでランプして保持 |
| `stop` | 0 Hzを設定。キュー遅延後に三相Low |
| `m 0.7` / `m auto` | 測定用の振幅固定/自動復帰。角度も同時に更新 |
| `profiles` | プリセット名を列挙 |
| `profile jr-fall` | 停止中にJR下降・急上昇の近似音パターンを選択 |
| `profile pmsm-toshiba` | 停止中にPMSM風の音作り用パターンを選択 |

指定範囲は0～110 Hz。範囲外・非数・不正行は無視する。物理ボタンが押されるとUSB保持を解除してボタン操作に戻る。`f`は測定用で周波数を急変させるので、通常の加速確認には`r`を使う。ログは`m_cmd`（所望の基本波電圧率）と`m_ref`（比較器に入れる正弦波振幅率）を分けて表示する。

## 出力と数値表現

- 基本波・キャリアの制御計算はFs=100,000 Hz、1フレーム10 µs。
- 各フレーム内で比較器の符号が変わる時刻を線形補間し、出力値と継続時間をPIOへ送る。三角波は山・谷で区間を分け、折り返しをまたぐパルスも扱う。
- PIOはclk_sysで動き、既定125 MHzではエッジ指定は8 ns刻み。1ワードを処理するOUT/OUT/JMPのため最短区間は3クロック=24 ns。それより短い区間は併合する。計算モデル、LUT、GPIO、ロジアナの誤差は別にある。
- 32 bitの無符号DDS位相。`Δφ = round(f1 × 2^32 / Fs)`。
- 正弦波LUTは2048点、符号付きQ15。既存IGBT/GTOの所望基本波電圧率は `m_cmd=min(f1/100, 1)`。非同期/N=9/N=15では比較器の振幅も同じ。N=3では後述の基本波ゲイン補正を入れる。
- 指令が0.01 Hz以下では全出力Lowとし、生成側の位相をゼロに戻す。
- 通常運転の停止指令はキューを経由するため即時停止ではない。
- 三角波を-32768～32767へ折り返し、`sin_Q15 × m_ref_Q15 / 32768 > triangle` の交点を求める。
- 初期化時だけsinを計算する。出力フレーム生成中は整数演算のみ。公開プリセットの振幅や角度のpow計算はmain側の指令更新で行い、IRQ内では行わない。
- 基本波分解能は約0.0000233 Hz、DDS丸め誤差は最大約0.0000117 Hz。LUTの位相量子化は約0.176°。
- Fs=100 kHzでは1 kHzキャリア1周期に100計算点あるが、エッジを計算点へ丸めない。最初の10 µs刻みの出力方式では低変調率に約10 µsのパルス幅下限が発生していたため、この方式に修正した。
- `vvvf_sample`/`vvvf_render`は比較器の制御点値を検証するためのAPI。実際のPIO出力は`vvvf_render_timed`だけを使う。
- PIOの分周は1。1フレームはclk_sys/Fsクロックで、既定125 MHzでは1250クロック。周期のずれを防ぐためclk_sysがFsの整数倍でなければ初期化時に停止する。

公開プリセットは生振幅と広域3/1パルスを含むため、従来SPWMとはパラメータの意味が異なる。[公開データの移植仕様](preset-sources.md)を参照。

## 非同期と同期の定義

非同期は独立したキャリアDDSであり、`Δcarrier = round(fc × 2^32 / Fs)` とする。今回ランダムディザは実装しない。

同期Nは **基本波1周期あたりのキャリア周期数**、すなわち `fc=N×f1` と定義する。出力立ち上がり数や半周期のパルス数とは区別する。3パルスも正弦波と三角波の比較で生成し、旧コードの6ステップには切り替えない。特定車両の実波形を再現したパルスパターンではない。

同期キャリア位相は `φc = N×φ1 + 0xC0000000 (mod 2^32)`。基本波θ=0でキャリアが下降側のゼロになる関係を固定する。別々の位相加算や周期ごとの強制リセットを使わないため、整数の周波数比に累積誤差がない。

最初の実装のoffset引き継ぎでは、N=3でモード変更履歴により基本波電圧が変わることが分かったため廃止した。基本波位相は維持するが、モード変更時にはキャリア位相が変わり得る。変更はブロック単位で、基本波ゼロクロス待ち・パルス幅連続化は実装していない。

### N=3の基本波電圧補正

低キャリア比の自然サンプリングSPWMでは、正弦波指令振幅と実際の基本波振幅は一致しない。固定した位相関係のN=3は、比較器振幅率1で正規化基本波が約1.27となる。そのため比較器振幅をそのままV/f値にしない。

`voltage.c`の`sync3_reference[33]`逆ゲイン表で所望基本波電圧率から`m_ref`へ変換する。例えば`m_cmd=1`に対して`m_ref≈0.799`、`m_cmd=0.55`に対して`m_ref≈0.469`となる。基本波の正規化は `m_eff=2×|Vuvの基本波ピーク|/(sqrt(3)×Vdc)`。これはGPIOを理想0/Vdcとした論理波形上の値であり、実際のモーター端子電圧ではない。

表は`tools/generate_sync3_table.c`で生成し、実機で55/100 Hzなどの基本波を測って確認した。N=3のキャリア位相、比較方式、波形を変えた場合は表を再生成して再測定する。任意のNや過変調を一般的に補償する仕組みではない。

## 周波数テーブル

各範囲は下端を含み上端を含まない。既定は`jr-fall`（JR墜落プリセット）。`include/vvvf/config.h`の`VVVF_DEFAULT_PROFILE_NAME`で変更できる。USBで`stop`の後に`profile gto`などを送ると切り替えられる。追加の`jr-fall`と`pmsm-toshiba`の曲線と精度は[音再現パターン](audio-patterns.md)を参照。

| IGBT基本波 Hz | モード |
|---|---|
| 0～40 | 非同期、fc=1000 Hz |
| 40～50 | 同期N=9 |
| 50～110（上限含む） | 同期N=3 |

| GTO基本波 Hz | モード |
|---|---|
| 0～2 / 2～4 / 4～6 / 6～8 | 非同期175 / 197 / 223 / 234 Hz |
| 8～10 / 10～12 / 12～14 / 14～16 | 非同期262 / 294 / 312 / 350 Hz |
| 16～46 | 非同期400 Hz |
| 46～60 | 同期N=15 |
| 60～70 | 同期N=9 |
| 70～110（上限含む） | 同期N=3 |

ビルド対象だった元コードの境界を優先した。GTOの未定義だった80 Hz以上はN=3を継続する仕様を追加した。`old/main.c`にあったN=1やN=5の別テーブルは採用していない。境界ヒステリシスはなく、上下操作で境界をまたぐたびにモード変更する。

## PIO・DMAと並行処理

PIO0の1 SM、3命令、TX FIFO結合、2 DMAチャネル、DMA_IRQ_0を専有する。SMとチャネル番号はSDKで動的確保する。ワードの下位3 bitがW/V/U、上位29 bitが継続クロック数-3。autopull閾値は32 bit。OUT pins、OUT X、JMP X--のループで指定時間だけ出力値を保持する。

A/B各256制御フレーム（2.56 ms）を先に生成する。各フレームは最大20ワードを確保し、各バッファの容量は20480 byte。実転送ワード数は交点の数で変わる。DMA A完了でBへ、B完了でAへハードウェアチェーンする。IRQで消費済みバッファを再生成して次のチェーンに備える。CPU IRQ頻度は約390.625回/s。バッファ生成の時間制限は約2.56 msであり、FIFOの先読みと割り込み遅延も余裕から差し引く必要がある。

mainは同じコアで短時間IRQを禁止して指令構造体を一括公開する。DMA IRQは次のブロック生成にそのスナップショットを使う。core1からの公開には対応しない。指令反映の待ち時間は通常最大約5.2 msにmainの入力ポーリング最大約10 msなどが加わる。USBログは500 msごと。

ログの`render_max`はバッファ生成だけの最大所要µs。IRQに入るまでの遅延や転送再設定の時間は含まないため、この値だけで期限達成を証明できない。

PIO TXSTALL、両DMA同時完了、再生成後に相手DMAが停止していた場合を異常とし、PIOを無効化して3ピンをSIOのLowに切り替え、faultをラッチする。復帰は再起動。割り込みが長時間止められた場合、その間は異常検出できず最終出力値が保持され得る。これはハードウェア非常停止ではない。実行中のフラッシュ消去・書き込み、長時間のIRQ禁止、DMA_IRQ_0の他用途との共有は行わない。

## 接続上の範囲

出力は三相の論理信号のみ。相補出力、デッドタイム、ゲートドライバ制御、電流検出、過電流遮断、DC電圧補償は含まない。実際のパワー段にはそれらを別途設計する必要がある。全出力Lowがパワー段を安全に停止するかは外部回路次第。まず信号のみを測定する。

PIO/DMAのAPI参考: [公式SDK Hardware APIs](https://www.raspberrypi.com/documentation/pico-sdk/hardware.html#hardware_pio)。
